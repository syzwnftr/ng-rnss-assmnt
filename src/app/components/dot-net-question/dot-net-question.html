1. What Is a Web API?

Web API is a set of rules or protocols that provides interaction between web / software applications. It acts like a bridge between two systems, letting one system request data or perform actions provided by another system over the web.

Metaphorically: An API is like a waiter in a restaurant that will serve us the food (data) based on the order (request) that we (the app) made.

3. State differences between MVC and WebAPI

MVC (Model-View-Controller) is used to build web applications that return both views and data for users. Meanwhile, Web API is used to build services that return data (like JSON or XML) to be consumed by other applications.

So in short, use MVC when we need to return a web page and use Web API when we want to return data to another application.

4. Who can consume Web API?

Web APIs can be consumed by a wide variety of clients because they are designed to be accessible to any platform that can make HTTP requests.

For example:

  • Web application
  • Mobile application
  • Desktop application
  • IoT devices
  • Command line tool / script

5. What is SSO based authentication?

SSO (Single Sign-On) is an authentication method that allows a user to log in once and gain access to multiple applications or systems without logging in again for each one.

Metaphor: It's like our ID badge that we use to enter our office building. At the front desk, we scan or show our ID badge to enter into the building. Now, once we enter the building, we now have access to other rooms within our boundary like our office room, meeting room, cafeteria, etc.

Example: Google account. Once we log in, we can access Gmail, Calendar, Google Drive, etc. without having to enter a password again for each application.

6. What kind of authentication is available for Web API? List 2 and elaborate.

There are a few authentication options available for Web API, but two common ones are:

Token-based authentication (e.g., JWT):

  • We log in once and get a special key (called a token) that proves who we are.
  • We use this key every time we talk to the API.
  • The API checks the token, and if it’s valid, we’re allowed in and can access the data.
  • This method avoids sending our username and password every time.

HTTP Basic Authentication:

  • Every time we send a request to the API, we include our username and password.
  • The API checks if the info is correct and lets us in.
  • It’s easy to implement but considered insecure because credentials are sent each time.
